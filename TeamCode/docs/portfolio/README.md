# Engineering Portfolio Notes

We write down our engineering story **as it happens**, so we don't have to remember it at the end of the season.
Each entry is one story: a problem, what we tried, what we found, and what we decided.
When it's time to build the real Engineering Portfolio, we pick the best entries from here.

> These notes are **raw material**, not the final portfolio. Check this season's Competition Manual
> for the portfolio rules (page limits, what each award looks for).

## How to write an entry
1. Copy `_template.md` to a new file named `YYYY-MM-DD-short-topic.md` (e.g. `2026-10-03-pinpoint-tuning.md`).
2. Fill it in **while you work**, not weeks later. Rough notes are fine; you can clean them up later.
3. Put real data in: measurements, tables, what went wrong. **Failed attempts count!** They show real engineering.
4. Add photos to `images/`. **Resize them first** (under ~1–2 MB each) so the repo doesn't get huge.
5. Link the GitHub issues, PRs and decisions (`TeamCode/docs/decisions.md`) the story is about.
6. Add your entry to the index below.
7. Open a PR like any other change.

**Where things go:**
- **Issues:** the raw work in progress (checklists, data as you collect it)
- **Decision log** (`decisions.md`): short record of *what* we chose
- **Portfolio entries** (here): the *story* behind it, with the evidence

**Using AI help?** If Claude or another AI assistant helped with part of the work, say so in the entry.
Judges care about what *the team* learned and did, so be honest about who did what.
